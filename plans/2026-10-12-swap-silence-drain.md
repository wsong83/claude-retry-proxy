**Two measured facts that constrain the implementation — do not "fix" them away:**

1. **`socket.timeout` permanently poisons an `http.client` response.** `socket.SocketIO._timeout_occurred` is set on the first timeout and never reset, so every subsequent read on that response raises `OSError: cannot read from timed out object`. Measured on this box (Python 3.14; `read1` after a 2 s timeout, upstream resuming 4 s later: reads 3 and 4 both raised). The existing chat drain already depends on this — it `break`s on `socket.timeout` and never re-reads. **A stream that times out cannot continue**, so there is no "wake and resume" rule anywhere in this plan: an armed timeout is terminal by construction, and the only question at the wake is *how to close* (EVICT vs today's cut).
2. **The upstream connection's socket timeout is 300 s** (`http.client.HTTPSConnection(host, port, timeout=300)` at `server.py:1181`/`1183`, documented at `doc/architecture.html:45,86`). Any unconditional re-arm to a smaller value silently replaces that documented stall tolerance. The arm is therefore conditional per read iteration (`_config_swapping` only) — a no-swap stream must keep the connection's original timeout byte-for-byte.

## Summary

**The failure this plan fixes.** `/admin/api/switch` (the admin page's Apply button) and `/admin/api/reload` (the Reload Providers button / CLI `reload`) currently use drain-and-swap with a **wall-clock 30 s drain deadline** (`server.py:2929-2943`, `3020-3034`): the handler sets `_config_swapping`, waits for `_inflight_count == 0`, and on timeout **aborts with 503 `{"error":"config swap timeout: requests still in-flight"}` and applies nothing**. `_inflight_count` increments at request admission and decrements only when the whole request finishes — including the full streaming duration of a generation and every retry-backoff sleep. With 3–4 Claude sessions working in parallel (and especially when switching *because* of rate limiting, when the in-flight set is full of 429-backoff sleepers holding the count for minutes), the drain essentially never reaches zero within 30 s: every Apply freezes all new requests for 30 s and then fails, applying nothing.

**The new design (all decisions user-confirmed in the 2026-10-12 discussion, plus four re-confirmed after the Phase 4.5 mega-audit — see below):**

```
press (Apply/Reload)
  ├─ single-flight: a second press while _config_swapping → 409, no drain entered
  ├─ pause new admissions (existing _config_swapping gate)
  ├─ stamp the shared activity clock; capture drain start
  ├─ snapshot _inflight_count  → reported as inflight_at_swap
  ├─ reset _swap_evictions = 0
  └─ retry chains abandon at their next checkpoint  → 503 config_swap_restart
drain (admin thread)
  while count > 0 AND (now - last_upstream_activity) < budget:  sleep 0.1
  exit A: count == 0        → everything left the set
  exit B: quiet ≥ budget    → all remaining are silent (guaranteed: the clock
                              resets on ANY upstream byte, so no byte in the
                              window ⇒ each one silent ≥ budget) → swap anyway
  drained = (_swap_evictions == 0)   ← "nothing was evicted", NOT the exit branch
swap (under lock): disk write / candidate install, then _config_epoch += 1
  └─ the epoch bump is the eviction signal for stragglers
release paused requests (existing _swap_done) → they snapshot the NEW config
return 200 with {drained, waited_s, inflight_at_swap}
stragglers (old-epoch) die at their next checkpoint, whenever it comes:
  mid-stream → in-stream retryable error close at its next read/wake
  pre-first-byte / buffered → 503 config_swap_restart on wake
```

- **One shared silence counter, not per-request timers.** `_last_upstream_activity` is reset by any upstream byte from any in-flight request (read sites touch it). The drain waits while *count > 0 and activity is fresh*; when the clock reads "nothing for the full budget", every remaining request is silent ≥ budget **by construction** — the drain's quiet exit fires only in a guaranteed all-silent state. Its two consequences were accepted: a zombie is only *declared* dead at total quiet, and when the last exit is a zombie rather than a natural finish, the swap waits up to one extra budget for the total-quiet confirmation.
- **Anything from upstream counts as progress** (including keepalive/ping frames); a finished response sends nothing more — its body ends (EOF) and the request leaves the set immediately. The residual case — an unfinished-but-stuck upstream that keeps pinging — is accepted (it dies by EOF/socket error when it actually dies; its client may disconnect it earlier).
- **Live work is waited to completion, unbounded by wall-clock.** A healthy generation of any length finishes and is delivered; only genuinely silent requests are evicted (silence budget, `PROXY_SWAP_SILENCE_TIMEOUT`, default 30 s). No absolute backstop (accepted — see the accepted-risk entry below).
- **`drained` means "nothing was evicted", and `inflight_at_swap` is the count at the press** — both snapshotted at press, so neither depends on which drain exit wins the race with a post-press eviction's counter decrement. `waited_s` is the drain wall-clock.
- **Swaps are single-flight.** `switch` and `reload` share one press/release cycle; while `_config_swapping` is True a second press is refused with 409 and enters no drain. Only the owner clears `_config_swapping` / `_swap_started_at` and sets `_swap_done`.
- **Retry chains abandon at press.** Chains are proxy-managed idling aimed at the provider being left, holding no generation work; they return a retryable 503 immediately, and the client's own retry lands (paused, then released) on the new mapping. This is what makes the drain usually *succeed* quickly and keeps Apply latency near the longest live generation.
- **Stream reads arm short only while a swap is in progress.** Per read iteration a stream loop sets its upstream socket timeout to `SETTINGS.swap_silence_timeout` when `_config_swapping` and to the connection's original 300 s otherwise. This is a **measured constraint, not a style choice**: `socket.timeout` permanently poisons an `http.client` response — `socket.SocketIO._timeout_occurred` is set on timeout and never reset, so every later read raises `OSError: cannot read from timed out object` (measured on this box's Python 3.14; the existing chat drain already relies on it by `break`ing rather than re-reading). An armed wake can therefore only ever *end* a stream, never resume one, and a timeout is treated as terminal by construction. Two consequences: no-swap stalls keep today's exact 300 s tolerance, and a straggler parked in a blocking read at the moment of the press still exits late (up to the 300 s socket timeout).
- **No old-routing result is ever delivered after the swap.** The epoch check is placed after each read and before the bytes are forwarded, so a straggler stops at its next read boundary; the residual chunk-granularity window (bytes already read under the old routing when the epoch bumps) is the accepted TOCTOU bound of "stragglers die at their next checkpoint".
- **Late exits accepted** for reads that cannot be woken (no cross-thread socket surgery): a request parked in a blocking read fails at its next wake (upstream answer, socket timeout, or a stream loop's armed budget wake while a swap is in progress). It never forwards the old-routing result.
- **Compat re-issues are NOT aborted at press** (immediate, bounded, part of completing an in-flight request; `test_compat_config_swap_during_retry` pins this). They are epoch-checked like everything else once the swap completes.

**Accepted risks (recorded, not mitigated):**

- **A swap can block every new admission for as long as the drain runs.** `forward_request` waits on `_swap_done.wait()` with no timeout, so while `_config_swapping` is True — now unbounded by wall-clock — new requests stall. The scenario that never terminates is the residual one above: an upstream that is stuck but keeps sending bytes, keeping the activity clock fresh forever. The escape hatches already exist and bypass the swap gate entirely: `claude-retry-proxy stop` (kills the process) and `POST /admin/shutdown` (never checks `_config_swapping`). Nothing else releases writers. This is documented in the drain docstring and `doc/architecture.html#config-swap`.
- **A live-but-slow request is evicted as if silent.** The quiet-implies-all-silent argument proves silence, not death. A request with no first byte yet (a long pre-fill/TTFT) or an unusually long inter-token gap is indistinguishable on the shared clock and is evicted retryably like a zombie. Raise `PROXY_SWAP_SILENCE_TIMEOUT` if this is hit in practice.

**Alternatives considered and rejected:** keeping a wall-clock cap and forcing the swap at expiry (rejected — kills healthy generations and buys quiescence only when idle-ish anyway); per-request silence registries (rejected — the single shared clock is sufficient by the quiet-implies-all-silent argument and simpler); cross-thread socket shutdown to wake parked readers (rejected for v1 — invasive; addable later); an absolute "never wait longer than X" backstop (rejected — silence + natural ends bound everything, and the operator keeps restart as an escape hatch); blanket socket arming to the budget for the whole stream life (rejected after the Phase 4.5 measurement — it silently replaces the documented 300 s stall tolerance and kills healthy no-swap streams with a >budget gap); serializing a second press by queueing it behind the first (rejected — the admin page would wait on a request that has not started; a 409 is truthful); asserting the exit branch as `drained` (rejected — a post-press eviction can decrement the count first, making the field a race rather than a fact).

**Out of scope:** cross-thread wake of blocked reads; arming buffered-body reads (`getresponse()` cannot be woken while blocked, and buffered bodies keep their 300 s timeout — their stall exits late, then fails the epoch check: recorded boundary); any change to compat retry semantics; prompt-cache/cost work; `scripts/analyze_proxy_trace.py` (no event enumeration there); the admin CSRF/endpoint posture (unchanged); the DNS-rebinding weakness of the localhost-only admin check (pre-existing, unchanged).

### What landed

The **silence-based drain-and-swap**: the old 30 s wall-clock drain — whose timeout is what made Apply fail under load — is deleted. A config press now pauses new admissions and drains while any in-flight request is still receiving upstream bytes, exiting only after `PROXY_SWAP_SILENCE_TIMEOUT` (default 30 s) of silence from *every* survivor, plus a 2 s quiet grace. Live work is waited to completion; retry chains abandon at the press with a retryable `503 config_swap_restart`; silent stragglers are evicted the same way; old-epoch requests die retryably at their next checkpoint, so no old-routing result is delivered after a swap.
