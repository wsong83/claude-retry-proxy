## Summary

**Problem.** `tests/test_chat_sse.py` is now the repo's largest file (5,358 lines, 82 tests) after the admin partition landed, and the largest of the eight test modules over the 1,500-line survey threshold (`tests/_harness.py`, 2,033 lines, is the separate over-threshold non-test helper and stays out of scope; survey re-run 2026-11-26 at commit time: code 1,000 / tests 1,500, `wc -l` physical lines).

**Approach.** Feature-area partition into four sibling files plus a shrunk `tests/test_chat_sse.py`, per guide §8/§9 (test threshold → feature-area partition preserving suite count and aggregator registration). The areas follow the file's own seams: core stream conversion (the keeper), stream termination + drain semantics + frame cap, tool-call synthesis/degradation + nesting limits, the retry-nudge family, and config-swap races. Membership is the product of a full AST free-variable resolution (the method the admin partition's mega-audit validated after falsifying the first regex map): every module-level name — 97 defs, 5 non-`ALL_TESTS` assigns — is covered by exactly one group, per-group import blocks are the measured sets, and the single multi-group seam (the trace-polling helper block) resolves by keeping the block byte-intact in the drain file with pinned sibling imports.

**Key decisions.**
- `test_chat_sse.py` survives as the core-conversion keeper — no file deletion, no retire hand-off.
- `test_chat_nudge.py` mirrors the `chat_nudge.py` module name (the `test_swap_drain.py` precedent).
- The trace-polling block stays byte-intact in the drain file; the four sibling-import lines above are the entire cross-file coupling surface. The byte-identical-to-harness duplication it carries (`_trace_events_named`) is recorded as follow-up, not fixed in a move.
- Byte-identity is verified name-keyed against `git show HEAD:tests/test_chat_sse.py` (AST source segments, sha256 per name); both gates also run dependency resolution and import-set exactness, so the NameError defect class the admin mega-audit found fails at Step 1 instead of mid-suite.
- The aggregator gains four imports; total registration stays 82 with zero name changes. Per-file `ALL_TESTS` order follows the pinned lists (a deliberate execution-order regroup, declared; `run_cli` runs sequentially and the tests are fixture-independent — proven by the admin partition's identical arrangement running green).
- Carried comments move as new text — AST segments cannot see comments, so this is the one part of the move the byte-identity gates cannot verify; the create/finalize gates therefore check **presence** of every pinned comment string. The pinned inventory lives in Step 1 with exact HEAD line ranges: the constant rationale blocks (`DRAIN_BOUND_TEST_SECONDS`, frame cap, config-swap budget), the section banners that head moved members (frame cap, retry-nudge, config swap), and the `ALL_TESTS` provenance lines.

**Alternatives rejected.** Folding the swap tests into the drain file (combined ~1,830 lines — over threshold); consolidating the trace helpers into `_harness.py` (design change beyond a move; recorded as follow-up); partitioning the remaining eight over-threshold test files in this plan (one cluster per plan).

**Out of scope:** the other seven over-threshold test modules (parallel track, own plans); any change to `_harness.py` (including the recorded follow-up of consolidating the byte-identical `_trace_events_named` copies and adding a standing suite assertion for the harness-before-package import order across `tests/*.py`, so that rule outlives this plan's transient gates); any behavioral change to any test; `CLAUDE.md` and `README.md` (neither enumerates test files).

**Architecture:** unchanged at runtime — same 82 tests, same names, same suite entry point, same per-file standalone entry points.
