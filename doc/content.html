claude-retry-proxy DocumentationA multi-provider HTTP retry gateway for the Claude API

Last updated: 2026-09-12

The proxy listens on localhost, routes requests by model tier (haiku / sonnet / opus) to different upstream providers, retries 429 and 503 responses with jittered exponential backoff, and logs every request to a JSONL trace file. Tier routing is configured in config.json; provider credentials are stored encrypted and decrypted at startup.

These pages are the deep reference. For installation and first-run setup, start with the README.

Contents

  • Architecture — the request path end to end: tier resolution, config and key lookup, forwarding, retry and backoff, the drain-and-swap pattern, and the trace/state sink failure policy.
  • Provider Modes — the anthropic, chat, and response modes: auth headers, path rewrites, request and response transforms, SSE synthesis, and tool-call handling.
  • Configuration — the config.json and keys-index.json schemas, multi-key selection, extra request headers, the full environment-variable table, and validation rules.

  • Test Catalog — the test suite layout, the per-test index of every test in the suite, harness isolation, and testing patterns.

Suggested reading order

Step 1

Skim README.md for the shape of the thing — what it does, how it is installed, what a config file looks like. It is self-contained; you do not need these pages to get running.

Step 2

Read architecture.html. Everything else is a facet of the request path described there, and its section anchors are what the other pages and the project's CLAUDE.md link back into.

Step 3

Read the page matching the thing you are actually changing — provider-modes.html for upstream compatibility, configuration.html for settings, operations.html for the running process, compatibility.html for the learned-state machinery, or trace-log.html for diagnostics.

Conventions used in these pages

  • All pages link to each other relatively; there are no external links, so a URL you need is shown as code rather than as a hyperlink.
  • Section headings carry stable id anchors so other documents can link to a specific section — for example architecture.html#retry.
  • File paths shown as src/claude_retry_proxy/server.py are relative to the repository root unless they start with ~, which means the user's home directory.
  • Runtime paths beginning ~/.claude/ are per-user and are not part of the repository.
